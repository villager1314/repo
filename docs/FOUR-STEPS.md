# 四步实施与可行性核对 / Four-step review

版本：0.5.0。这里记录本轮实际结果；未完成的建议不视为已经支持。

## 第一部分：命令和参数体验

| 项目 | 结论与实际行为 |
| --- | --- |
| show、download、reinstall | 已完成；重装只允许相同版本，不绕过 Android 降级限制 |
| APKM 安装本地路径 | 已完成，直接委托 APKG；本地/源名称混用先拒绝 |
| 删除源中友好名称 | 已完成；Android 包名默认直接处理，友好名称依赖缓存 |
| APKG 的 DPKG 风格简写 | 已完成 -i/-r/-l/-s/-I/-c 及相应长选项；不是完整 DPKG 语法复刻 |
| 参数位置、-d、-? | 已完成；常用全局参数可后置，-- 后的内容保留为字面参数 |
| 模糊长参数缩写 | 已关闭，避免新增选项后改变旧缩写含义 |
| 搜索改进 | 已完成多关键词、--names-only、--exact；没有加入模糊正则语言 |
| -q/verbose、补全、配置路径 | 可行但本轮推迟；不影响现有 JSON/进度选项，需统一所有输出与配置读取 |
| 源管理启停、编辑、健康检查 | 可行但推迟；编辑需要校验和回滚，源启停需要一致覆盖更新/查询/选择 |

阶段检查：69 项测试通过后进入下一步。

## 第二部分：查询和维护

| 项目 | 结论与实际行为 |
| --- | --- |
| APKM list 语义 | 已改为缓存仓库列表，默认离线；这是与旧版不同的行为 |
| installed/upgradable 筛选、模式匹配 | 已完成；只覆盖仓库可识别应用，设备全集用 apkg list |
| 所有版本 | 使用 versions 查询缓存保留的版本/ABI 变体；未添加 list --all-versions 别名 |
| info/show 详情 | 源信息改为可读字段；APKG 状态增加 base/split 安装路径 |
| 本地包信息、归档内容 | 已完成 file-info/contents，离线读取；不把元数据解析当作签名验证 |
| 系统/用户应用筛选 | 已完成 apkg list --system / --user-apps |
| clean、cache-info | 已完成，限定工具管理的下载缓存；保留索引、用户文件和符号链接目标 |
| autoclean | 可行但推迟；需定义当前/历史多源索引对应的过期判定，现有 clean 范围更明确 |
| 提取到用户目录 | 可行但推迟；内部临时解压已受限，公开解压还需要明确覆盖/路径/权限规则 |
| 文件归属、完整性核验 | 不能声称等价于 DPKG；Android 私有文件权限、APK 签名及资源范围不同。先提供 APK 路径和 Android 安装验签 |
| 应用名称、全部状态字段 | 部分信息可获取，但资源引用和 OEM dumpsys 差异需要额外适配；目前不猜测缺失字段 |

阶段检查：73 项测试通过，新增清理边界、离线信息查询和列表测试。

## 第三部分：可解释操作控制

| 项目 | 结论与实际行为 |
| --- | --- |
| 模拟执行 | 已完成 --simulate/--dry-run；APKM 可用 -s，APKG 的 -s 留给状态查询 |
| 安装计划 | 已有逐项计划；预演不下载、不修改设备。不声称是整批原子事务 |
| 指定来源 | 已完成 --source，重复名称默认仍报错；没有静默源优先级或自动换签名 |
| 指定版本、候选查询 | 已完成 NAME=versionCode、versions、policy；仅限索引保留的信息 |
| hold/unhold/showhold | 已完成，仅约束 APKM upgrade，按连接标识保存；无线端口变化不沿用锁定 |
| 自动降级、跨签名迁移 | 不自动做；Android 可能拒绝降级，换签名可能涉及数据丢失，不能用强制卸载掩盖 |
| keep-data / purge | 条件可行但推迟实机测试；当前 remove 通常删除数据，不伪造 Debian 的 remove/purge 区分 |
| 多 Android 用户/工作资料 | 条件可行但推迟；安装/状态/版本/权限必须使用同一用户范围，需要实机权限矩阵 |
| 批量继续、总下载量、统一确认 | 可行但推迟。当前失败停止、先前成功不回滚；后续需完整计划及准确部分失败结果 |
| 持久日志、断点续传、重试、镜像故障切换 | 可行但推迟；需日志脱敏、Range/ETag/hash校验及可信源回退规则 |
| 并发锁、强空间预留 | 可行但推迟；现有大小限制不等于并发控制或磁盘空间保证 |

阶段检查：79 项测试通过，覆盖只读预演、连接隔离、版本与来源选择。

## 第四部分：复杂格式与发布

| 项目 | 结论与实际行为 |
| --- | --- |
| 多变体 APKS | 条件支持：--bundletool JAR，使用用户已安装的 Java 和官方工具按设备提取 |
| 默认安装 Java/JAR | 不做，保持 Termux 默认依赖轻量；没有自动下载或执行远程 JAR |
| 真实提取验证 | 官方 bundletool 1.18.3 成功提取一个手工构造的最小合法 toc.pb 归档；真实 APK Manifest 随后解析。设备安装仍模拟 |
| 内置 toc.pb 完整选择器 | 可行但不重复实现；官方工具覆盖复杂规则更可靠，当前采用可选适配器 |
| 独立归档 ABI/语言/密度规则 | 维持已验证的常见规则；未知目标拒绝。不是 Android/Play 全部配置算法 |
| OBB / Play Asset Delivery | 本轮不安装，OBB 仍明确提示跳过；资产下载涉及不同协议和权限 |
| APK 签名预检查 | 可选成熟工具有可行性，但本轮不增加依赖；最终一致性与更新签名由 Android 检查 |
| 第三方源 JAR 验签 | 可行但推迟，需要固定发布者证书、严格 JAR manifest/摘要校验和异常测试，不能仅解压 JSON |
| v2 增量索引、多镜像、GitHub Releases 源 | 推迟到对应签名/信任/元数据策略完善后；不绕过验证追求功能数量 |
| 英文运行日志、退出码细分 | 部分已有；完整日志本地化和跨后端状态映射仍需独立整理 |
| CI、版本/文档同步 | 本轮增加版本一致性检查，更新中英文 README、man/help、首页、软件源和 Release |

最终自动测试：85 项。另完成官方 bundletool 实际提取验证。没有宣称真实安卓设备、原生 Arch/ARM64/Termux 或所有 APKS/APKM/XAPK 厂商格式均已实机通过。

## 不照搬的 Debian 功能

- autoremove/full-upgrade/satisfy：目前没有 Debian 式依赖关系和自动安装标记模型，不添加空壳命令。
- configure/unpack/triggers：Android 安装会话模型不同，内部解压不是 Debian 的解包配置状态。
- --root/--instdir：不能把安卓应用安装到任意 Linux 根目录。
- --no-install-recommends：仍是安装 APKM 工具时的 APT 选项，不是 Android 应用依赖选项。
